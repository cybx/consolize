# consolize: consolidated fix list (most dangerous first)

35 raw findings deduplicated to 24. Items marked **[NO DESKTOP]** can leave a user with a controller, no Explorer and no way in.

---

### 1. `src/Consolize.SessionManager/Program.cs:230` — **[NO DESKTOP]**
`WatchdogLoop` and everything it calls run with no try/catch; the only handler is `Main`'s, which does `return 1`, i.e. it kills the process that *is* the Windows shell. Concrete throw site: `FindApp` (line ~366) enumerates `HKLM\...\Uninstall` and calls `OpenSubKey` on every subkey, which throws `SecurityException` for a limited user against any ACL'd key. Shell Launcher's default `RestartShell` then relaunches into the identical deterministic exception: infinite black-screen restart loop.
**Fix:** wrap the `while` body in `try { … } catch (Exception ex) { Log(ex); SleepCancellable(ct, delay); }`; wrap the per-subkey work in `FindApp` in `catch (SecurityException) { continue; } catch (UnauthorizedAccessException) { continue; }`; change `Main`'s catch from `return 1` to `EnterDesktop()` plus an idle loop. Exiting is the one thing this process must never do.

### 2. `setup/preflight.ps1:74` (+ `README.md:137`, `setup-console.ps1:62/105`) — **[NO DESKTOP]**
The "Steam has a saved login" check reads only `config\loginusers.vdf`, which is **machine-wide**, and runs as SYSTEM so it cannot see the console account's `HKCU\SOFTWARE\Valve\Steam\AutoLoginUser` (which `first-logon.ps1:69` correctly checks). The admin's own sign-in makes it PASS for an account with no credentials. Compounding it: a re-run of phase 1 with a different account name never deletes a stale `account-ready` marker (only `-Abort` at line 62 does), so the finish task skips the wait entirely and applies Shell Launcher to an account that never completed phase 2. First boot lands on the small Steam desktop login window with no Explorer behind it.
**Fix:** (a) resolve the target user's hive (`reg load` their `NTUSER.DAT`, or read `HKU:\<sid>\SOFTWARE\Valve\Steam\AutoLoginUser`) instead of trusting the shared vdf; (b) `Remove-Item $readyMarker` at the start of every phase-1 run, next to `Remove-ConsolizeTasks` (line 320); (c) stamp the marker with the account name and have `-Finish` reject a mismatch; (d) fix README:137 to say the sign-in happens *inside the gamer session*, not the admin one (README:86-87 already says so).

### 3. `setup/first-logon.ps1:86` + `setup/add-console-shortcuts.ps1:101` (+ `README.md:29,38`) — **[NO DESKTOP]**
`add-console-shortcuts.ps1` is only called inside the `else` branch of `if (Test-SteamLogin $steam)`, so the "already signed in" fast path (a re-run, a restored image, a hand-signed-in account) marks the account ready without ever adding **Desktop Mode** or **Quick Settings**. Second silent skip: the script refuses to touch a `shortcuts.vdf` that already has non-Steam entries. There is no global gamepad chord (`QuickSettingsForm` polls XInput only once open) and the tray icon exists only in desktop mode, so a controller-only user has zero escape routes. Preflight does not check for the shortcuts at all.
**Fix:** move the `& $shortcuts -Force` call out of the `else` so it runs on both paths once login is confirmed; teach `add-console-shortcuts.ps1` to **append** to an existing vdf instead of bailing; add a preflight check that the target user's `shortcuts.vdf` contains the Desktop Mode entry; ideally give the session manager a built-in always-on gamepad chord.

### 4. `src/Consolize.SessionManager/Program.cs:277` — **[NO DESKTOP]**
The watchdog equates "the process I started exited" with "the frontend is gone". `steam.exe -bigpicture` hands off to an already-running client and returns 0 in about a second (and Steam re-execs itself after a self-update), so the loop relaunches forever. Exit code 0 is never enqueued into `crashes` (line 285 only counts `exitCode != 0`), so the breaker can never fire. Each iteration calls `ShowSplash(proc)` with no re-entrancy guard, so 3-4 fullscreen TopMost splashes stack permanently over a perfectly healthy Big Picture.
**Fix:** after `Process.Start`, if the started process exits in under ~10s with code 0, look up the real frontend by name (`steam`, `Playnite.FullscreenApp`) in this session and watch *that* instead of relaunching; count any exit within a few seconds of start toward the crash window regardless of code; guard `ShowSplash` so only one splash exists and skip it when the last launch was less than `SplashSeconds` ago.

### 5. `setup/setup-console.ps1:324` — local privilege escalation to SYSTEM
`icacls $stateDir /grant "${UserName}:(OI)(CI)M" /T` grants the limited console account Modify, recursively, over `C:\ProgramData\Consolize` — and `get.ps1:19` installs the setup scripts to `C:\ProgramData\consolize\setup` (same tree; NTFS is case-insensitive). `ConsolizeFinish` (lines 336-343) runs `setup-console.ps1 -Finish` from there as **SYSTEM / RunLevel Highest at every logon**, and that script invokes `preflight.ps1` and `enable-shell-launcher.ps1` by path. Anything running as the gamer account (a modded game, an RCE in the frontend) appends a payload and owns SYSTEM on the next autologon, fully unattended. `answers.json` and `startup-backup.json` are writable by the same grant and are consumed by elevated code.
**Fix:** create a dedicated `C:\ProgramData\Consolize\state\` and grant only that (no `/T` on the parent), pointing `$readyMarker` there; move the setup scripts to `C:\Program Files\Consolize\setup` and run the SYSTEM task from there; verify the script path has no non-admin write ACEs before `-Finish` acts; treat `answers.json` / `startup-backup.json` as untrusted input.

### 6. `src/Consolize.SessionManager/QuickSettingsForm.cs:356` — unpairs the wrong device
Rows are rendered from `_btDevices.OrderByDescending(d => d.Connected).ThenBy(d => d.Name)` (line 212), a projection never written back, but `ForgetSelected` does `_btDevices[_list.SelectedIndex - 1]`. Any radio order that is not already (connected desc, name asc) silently forgets a different device than the highlighted one — including, plausibly, the gamepad the user is holding.
**Fix:** assign the sorted sequence back (`_btDevices = Bluetooth.GetDevices(...).OrderByDescending(...).ThenBy(...).ToList();`) and iterate `_btDevices` at line 212; better, capture the `BluetoothDeviceInfo` in the row closure as `RenderAudio` already does and drive Forget from the captured object.

### 7. `src/Consolize.SessionManager/QuickSettingsForm.cs:200,225,243` — **[NO DESKTOP, temporarily]**
`Bluetooth.GetDevices(scan: true)` (5s+ inquiry), `Bluetooth.Pair` (tens of seconds on a sleeping device) and `RunCommand("netsh", …)` (`WaitForExit(15000)`) all run on the WinForms UI thread. All input comes from `_padTimer`, a `System.Windows.Forms.Timer` pumped by that same loop, so during the block B/Back and Escape are dead and a borderless, maximized, `TopMost` window sits frozen over the frontend. On a console with no keyboard the only recourse is the power button. `_busy` is set *inside* the blocking call, so it guards nothing.
**Fix:** `await Task.Run(...)` all three, set `_busy` and the "scanning…" status *before* the await, and keep the pad timer alive so B always closes the panel.

### 8. `setup/first-logon.ps1:81` + `setup/setup-console.ps1:92,177` + `setup/enable-shell-launcher.ps1:33` — Playnite is offered but unfinishable
The interview lets the user decline Steam and pick Playnite, but phase 2 unconditionally calls `Get-SteamPath`, warns, leaves `loginConfirmed = $false`, falls to the else at line 167 and blocks on `Read-Host` without ever writing `account-ready`; the SYSTEM task then polls the full 3600s and gives up. Even with the marker, `setup-console.ps1:92` calls preflight with no `-Frontend`, so it defaults to `steam` (preflight.ps1:16) and FAILs on "Steam not installed". Neither task is unregistered, so this repeats at every logon on a machine that already has Defender off, startup emptied and bcdedit rewritten.
**Fix:** have `first-logon.ps1` read `answers.json` (or take `-BootInto`) and run the Steam gate only when the frontend is steam, gating on Playnite Fullscreen being launchable otherwise; pass `-Frontend $answers.BootInto` at `setup-console.ps1:92`; add a `-Frontend` parameter to `enable-shell-launcher.ps1` and forward it on line 33. Until that is done, restrict the interview at line 177 to Steam.

### 9. `setup/first-logon.ps1:130` — an unguarded `&` kills phase 2 after the sign-in
`& $shortcuts -Force` has no try/catch, while `add-console-shortcuts.ps1` sets `$ErrorActionPreference = 'Stop'` and `throw`s at its line 26 when `consolize.exe` is missing — a state `get.ps1:139-142` explicitly tolerates ("Setup scripts still work; grab the binary later"). A terminating error in a `&`-invoked child kills the caller regardless of the caller's EAP, so lines 148-166 never run: no marker, no message, the window just closes and the SYSTEM task waits an hour.
**Fix:** `try { & $shortcuts -Force } catch { Write-Warning "Could not add the Steam shortcuts: $($_.Exception.Message)" }`. Also check for `consolize.exe` at the top of `first-logon.ps1` and have `setup-console.ps1` refuse to register the tasks when the shell binary is absent.

### 10. `setup/power-console.ps1:33` and `:99` — aborts setup before anything is scheduled
`$out = & powercfg.exe @Arguments 2>&1` under `$ErrorActionPreference = 'Stop'` (line 26): in PS 5.1 `2>&1` wraps each native stderr line in an ErrorRecord, which becomes a **terminating** `NativeCommandError`, so the `Write-Warning` on line 34 is unreachable dead code. Triggers on ordinary hardware: a Modern-Standby mini-PC has no Ultimate Performance template so line 99 throws, and `-RestMode Hibernate` on a VM (including the project's own `testlab/New-TestVm.ps1`) makes `/hibernate on` throw. The exception propagates into `setup-console.ps1:306`, so `clean-startup.ps1`, `set-autologon.ps1`, both task registrations and the reboot never happen: Defender already off, boot UI already suppressed, no autologon, no path forward.
**Fix:** in `Invoke-PowerCfg`, `$prev = $ErrorActionPreference; $ErrorActionPreference = 'Continue'; $out = & powercfg.exe @Arguments 2>&1; $ErrorActionPreference = $prev` and keep the `$LASTEXITCODE` check. Apply the same to line 99 (or just drop the `2>&1` there).

### 11. `setup/enable-shell-launcher.ps1:42` — DISM 3010 treated as fatal, with a wrong diagnosis
`dism … /norestart` returns 3010 (ERROR_SUCCESS_REBOOT_REQUIRED) whenever servicing wants a restart, which phase 1 guarantees: `boot-silent.ps1` enables three Device Lockdown features with `-NoRestart`, NetFx3 likewise, updates with `-IgnoreReboot`. Line 42 throws and blames the Windows edition, `Remove-ConsolizeTasks` is never reached, and the machine loops forever.
**Fix:** `if ($LASTEXITCODE -ne 0 -and $LASTEXITCODE -ne 3010) { throw … }`; on 3010, log it and reboot so the reboot-driven `-Finish` task resumes, rather than calling `SetCustomShell` against a half-installed provider.

### 12. `setup/setup-console.ps1:75-108` — the finish path has no error handling and no transcript
`$ErrorActionPreference` is `Stop` for the whole file, the `-Finish` block has no try/catch, and `Start-Transcript` only runs in the phase-1 section (line 243). Any throw inside `enable-shell-launcher.ps1` (Test-Path guard, DISM check, NTAccount SID translation, three `Invoke-CimMethod` calls) terminates the task after `finish.log` last said "preflight passed, replacing the shell": no reboot, both tasks still armed, nothing tells the owner whether the shell was replaced.
**Fix:** wrap the whole `-Finish` body in try/catch, write `$_` to `finish.log`, and check the `WESL_UserSetting` CIM class is actually usable before proceeding.

### 13. `setup/preflight.ps1:77` — rejects exactly the sign-in the product recommends
Preflight accepts only `"RememberPassword" "1"`, while `first-logon.ps1:76` deliberately accepts `RememberPassword` **or** `AutoLogin` with a comment explaining that the QR sign-in never shows the checkbox, and lines 93-94 actively steer the user to QR. So phase 2 succeeds, phase 3 FAILs "Steam login is not saved" into a log nobody watches, and the machine silently never becomes a console. Its `HKCU:\...\Run` check (line 109) is also SYSTEM's hive, i.e. vacuous.
**Fix:** use the same predicate as `first-logon.ps1` (RememberPassword OR AutoLogin, plus the target user's `AutoLoginUser`), read the Run keys from the target profile's hive, update `docs/architecture.md:45-46`, and surface a repeated preflight failure on screen, not only to `finish.log`.

### 14. `setup/setup-console.ps1:332` — ConsolizeFirstLogon never runs on battery
Registered with no `-Settings`, so it inherits `DisallowStartIfOnBatteries = $true` / `StopIfGoingOnBatteries = $true`. `ConsolizeFinish` ten lines below explicitly passes `-AllowStartIfOnBatteries`, so the hazard was known and missed on one of the two. On a handheld, an unplugged laptop, or a UPS that reports as a battery, phase 2 simply never fires and the only record is a Task Scheduler event nobody reads.
**Fix:** build one `$commonSettings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries` and pass it to both registrations (the finish task currently only opts into *starting*).

### 15. `setup/clean-startup.ps1:38-39,56` — empties the administrator's startup, not the console account's
`Get-StartupItems` reads `HKCU:\...\Run`/`RunOnce` and `[Environment]::GetFolderPath('Startup')`, both of which resolve to the *running* user. `setup-console.ps1:309` calls it as `-All` while elevated as the installing admin, under the banner "Emptying Windows startup". The admin's OneDrive, password manager, backup agent and VPN are removed silently; the console account is never cleaned.
**Fix:** add `-ForUser`, `reg load` that profile's hive and enumerate `HKU\<SID>\...\Run` plus its Startup folder; or restrict the sweep to HKLM + `CommonStartup` when the target is another user. At minimum refuse `-All` non-interactively against a user other than the one in `answers.json`, and print which account is being emptied.

### 16. `setup/bootstrap-gaming.ps1:229-235` — `-Preset recommended` installs no launcher at all
The splat chain is `if ($Launchers) … elseif ($Preset -eq 'all') … elseif ($Preset -eq 'minimal') …`, so `recommended` sets no `Install`, while the next line still sets `BootInto = 'steam'`. `install-frontend.ps1`'s guard on line 74 is therefore false, the picker is skipped, and its `foreach ($key in $Install)` iterates zero times. This is the exact invocation the script header (line 5) and `docs/architecture.md` advertise: it spends minutes on updates, installs no frontend, writes `Frontend=steam` into config.json and reports success in green.
**Fix:** add `elseif ($Preset -eq 'recommended') { $splat['Install'] = 'steam' }` (or collapse to `elseif ($Preset) { $splat['Install'] = if ($Preset -eq 'all') { 'all' } else { 'steam' } }`).

### 17. `setup/install-frontend.ps1:66` — Playnite and Hydra land in the admin's profile
`winget install` runs in the elevated phase-1 session with no `--scope`; both packages default to per-user (`%LOCALAPPDATA%\Playnite`, `%LOCALAPPDATA%\Programs\Hydra`) and register only under the installing user's HKCU uninstall key. `Program.cs ResolveFrontend`/`FindApp` look under the *running* user's LocalApplicationData and `Registry.CurrentUser` + HKLM, so from the console account neither files nor registry entries exist, while machine-wide config.json says `Frontend = playnite`. Result: watchdog logs "no frontend found", falls back to `explorer.exe`, and the console boots to a bare desktop.
**Fix:** pass `--scope machine` where supported, or install these launchers from inside the console account during phase 2, and have preflight verify the resolved path *for the target user*.

### 18. `setup/power-console.ps1:46-58` — `-Restore` writes defaults into the wrong scheme and leaves a full-size hiberfil
The apply path activates a duplicated Ultimate Performance scheme (lines 96-103), so `-Restore` writes its "defaults" into *that* scheme and re-activates it; the user's original scheme GUID is never recorded. Restore also misses `SBUTTONACTION`, `LIDACTION`, USB selective suspend, `hibernate-timeout-ac`, every `setdcvalueindex`, and never runs `powercfg /hibernate off`, so a 32 GB `hiberfil.sys` stays allocated on a 256 GB console SSD with no indication why, and a laptop keeps console DC behavior while the owner believes power is back to normal.
**Fix:** record `powercfg /getactivescheme` and the prior hibernate state to a state file before applying; have `-Restore` reactivate the saved GUID, run `/hibernate off` when it was off, `powercfg -delete` the duplicated scheme, and mirror every setting the apply path touched (AC and DC).

### 19. `setup/boot-silent.ps1:39-51` — `-Restore` never undoes `bcdedit /timeout 0`
Line 77 sets `/timeout 0` on `{bootmgr}`; the restore block reverts only `{current}` values and has no `/timeout` line and no `{bootmgr}` reference anywhere. A dual-boot user runs `-Restore`, is told "the logo and welcome screen come back", and the other OS remains permanently unreachable.
**Fix:** capture the current value from `bcdedit /enum {bootmgr}` before setting it, restore it explicitly (default 30), and skip `/timeout 0` entirely when `bcdedit /enum` shows more than one boot entry.

### 20. `setup/setup-console.ps1:92-93` — the one diagnostic that matters is always empty
`$preflightOut = & … preflight.ps1 … 2>&1` captures nothing, because preflight emits everything through `Write-Host` (its `Write-Check`, lines 26-27, and the verdict block, 153-162), which goes to stream 6 and is not merged by `2>&1`. `finish.log` therefore records "preflight failed; NOT replacing the shell" and "fix the issues above" with the issues never written.
**Fix:** capture with `*>&1` (or `6>&1 2>&1`), or convert `Write-Check` and the verdict to `Write-Output`.

### 21. `src/Consolize.SessionManager/Consolize.SessionManager.csproj:4` — `WinExe` silently discards all console output
Subsystem 2 means no attached console, so `Console.Out` is a no-op sink: `send` (Program.cs:124/129), `--version` (87) and the whole of `PanelDiagnostics` (136-165) print nothing, and `$LASTEXITCODE` after `& consolize.exe send status` is meaningless because the shell does not wait. `install.ps1:23` tells the operator to run exactly that command. This matters most when the desktop is gone and a terminal is all you have.
**Fix:** `AttachConsole(ATTACH_PARENT_PROCESS)` at the top of `Main` for the `send` / `--version` / `panel --diag` branches, reopening `Console.Out`/`Error` after; or ship a CUI-subsystem `consolizec.exe`. Until then remove the `send status` suggestion from `install.ps1:23`.

### 22. `src/Consolize.SessionManager/Program.cs:638` — stale `_resumeConsoleRequested` defeats the crash-loop breaker
`EnterConsole()` latches the flag unconditionally, but only `IdleUntilConsoleRequested` (line 747) consumes it, and in the normal case the watchdog is parked in `proc.WaitForExit()` so nobody reads it. A later breaker trip calls `IdleUntilConsoleRequested(ct, 60s)`, sees the stale flag, returns in 0ms, and the machine flaps between a crashing frontend and a half-started Explorer every ~3s. The same stale flag makes `RelaunchOnCleanExit=false` fail to stick at line 281.
**Fix:** reset the flag at the top of `IdleUntilConsoleRequested` before waiting, or replace it with a `ManualResetEventSlim` reset on entry and waited on via `WaitHandle.WaitAny(new[]{ resumeEvent, ct.WaitHandle }, retryAfter)`.

### 23. `src/Consolize.SessionManager/Interop/Bluetooth.cs:234` — union laid out sequentially, `negativeResponse` at the wrong offset
Native `BLUETOOTH_AUTHENTICATE_RESPONSE` is 48 bytes with the union at offset 12 and `negativeResponse` at **44**; the C# struct puts `pinInfo` byte[32] at 16..47 and `negativeResponse` at **48**, so the stack always reads a zero from inside the null-marshalled array. The clean-refusal branch at line 155 (`negativeResponse = 1`) is dead code: a legacy-PIN or passkey device gets an affirmative response with passkey 0 and the call blocks until the pairing timeout, on the UI thread (see item 7).
**Fix:** `[StructLayout(LayoutKind.Explicit, Size = 48)]` with `bthAddressRemote` at 0, `authMethod` at 8, numeric/passkey at 12, `pinInfo` at 12, `negativeResponse` at 44; assert `Marshal.SizeOf == 48` and `Marshal.OffsetOf(nameof(negativeResponse)) == 44` in a test, and initialise `pinInfo` instead of leaving it null.

### 24. `setup/boot-silent.ps1:86` — `BrandingNeutral` written to the wrong key, with the wrong value
Custom Logon reads `BrandingNeutral` from `HKLM\Software\Microsoft\Windows Embedded\EmbeddedLogon`; only `AnimationDisabled` lives under `…\Authentication\LogonUI`. The value is also a bitmask (1 = logon buttons, 2 Power, 4 Language, 8 Ease of Access, 16 Switch user, 32 Blocked Shutdown Resolver), so `1` does not suppress Switch user or the BSDR screen the file header promises. The script reports success and `-Restore` deletes a value that never did anything.
**Fix:** write to `HKLM:\SOFTWARE\Microsoft\Windows Embedded\EmbeddedLogon` with `0x1 -bor 0x10 -bor 0x20` (49), and add `HideAutoLogonUI = 1` and `HideFirstLogonAnimation = 1` in the same key.
